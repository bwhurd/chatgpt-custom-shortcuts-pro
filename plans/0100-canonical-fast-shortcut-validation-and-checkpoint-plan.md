## Design and invariants

- [ ] Keep `npm run test:shortcuts:fast` as the one portable execution command. It builds its catalogue once and runs available cases once. `npm run shortcuts:catalog` remains the optional browser-free listing; no mandatory catalogue-then-saved-acceptance chain. Luna is useful for repairing findings, not required to operate the deterministic command. Do not create a personal Codex skill.
- [ ] **User clarification:** missing cases produce a concise warning section at the end; they must not kill validation or stop independent cases. Missing metadata/adapter/coverage and unknown requested IDs/types are warnings with row/source/owner/reason. Retain untested/unsupported status and a complete-versus-partial coverage label. Warning-only runs return success with warnings; a zero-case run explicitly says no checks ran.
- [ ] Continue after per-case failures too, collect all settled results, close owned pages, and print/save the summary. Exercised target absence, wrong effects, runtime errors, environment failures affecting an attempted case, or a broken serial barrier produce a nonzero exit after reporting. Unrecoverable startup/source errors report the blocked scope; do not pretend checks ran. Never downgrade an observed product failure to a coverage warning.
- [ ] Keep filtered runs useful: selected rows get results, other implemented rows remain intentionally unselected, and only genuine missing coverage is warned. Do not treat an intentionally filtered run as full coverage or fail it for unselected rows. Catalogue mode makes no execution claim.
- [ ] Reuse and reconcile current runtime/default/schema/options/metadata sources instead of creating another hand-maintained shortcut list. Include fixed contracts, both sparse model profiles, declared browser commands, and new first-party keyboard-listener sites derived from the manifest. Unknown sites/actions stay visible. Do not infer DOM targets from localized text or arbitrary function bodies.
- [ ] Automatically catalogue the Chrome popup command and validate its declared popup target exists. Label that proof static wiring; browser-native activation remains an explicit warning/external boundary. Do not add a slow authenticated/persistent-extension fixture for it.
- [ ] Preserve blank bindings, array holes, profile-specific duplicate rules, and fixture-only assignments. Never reuse the user's live extension storage. The workflow must work from a fresh clone without manual keys, private JSON artefacts, personal URLs, Windows tools, or AI access.
- [ ] Controlled DOM fixtures establish code dispatch/target/effect against their recorded structural states. They do not establish current live ChatGPT selector availability, OS clipboard permissions, transcription/playback, upload completion, or network/account outcomes. Keep functional targeted live/selector diagnostics available for reported drift; do not run them routinely or brand fixture results as an all-hotkeys-live pass.
- [ ] Keep the ten-tab pool and production wait semantics. Print timings for diagnosis; do not make a noisy machine-speed threshold a routine contributor failure. No exhaustive variants, wide scrape, conversation provisioning, popup screenshots, or external recovery in the default shortcut check.
- [ ] Preserve intentional existing work and accurately retain incomplete product-plan status. User authorization includes normal reviewed commits/pushes for this checkpoint. Never obtain a clean tree through reset, deletion, stash-and-forget, force push, or secret inclusion.
