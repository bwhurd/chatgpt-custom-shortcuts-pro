## Invariants and risks

- [x] Add no mutation observers, timers, polling, or test hooks to shipped runtime. Bounded assertion retries belong only in tests. Keep runtime behavior and translations unchanged.
- [x] Never disable whole correctness rule families or ignore maintained runtime/validator files to obtain green results. Each exclusion needs a path-specific ownership explanation and proof that maintained inputs are still checked.
- [x] Avoid broad formatter/fixer commands and unsafe automatic fixes. Apply targeted formatting only to approved maintained inputs, preserve existing formatter exceptions for `content.js`/`popup.js`, and inspect behavior-sensitive suggestions individually.
- [x] Use isolated synthetic fixture directories/profiles, restore monkeypatches in `finally` if needed, and clean only owned temporary paths. Tests must not mutate the real extension, user settings, or committed fixtures. Prefer small fixtures exercising the public validator API over snapshotting implementation details or copying the entire repo.
- [x] Respect platform-specific screenshots: final browser gates run on Windows with the existing local Chromium dependency. Do not silently skip missing baselines, increase image tolerances, suppress unexpected browser errors, or auto-update snapshots. An intentional baseline update requires a concrete reviewed rendering reason; absent that, investigate the regression.
- [x] No wholesale rollback: if a batch needs reversal, undo only its verified edits; retain the user's work and record remaining failures. Do not use destructive Git commands.
