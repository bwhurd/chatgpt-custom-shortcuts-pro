## Design decisions and invariants

- [x] Resolve a unique semantic main on Library routes (`main` / `[role="main"]`, preferring observed shell marker) without generated IDs. Refuse ambiguous candidates; never fall back to arbitrary document-wide file/button matching.
- [x] Enumerate `[data-library-item]` within that root. Read list filenames from the marked name cell's opening button (row aria-label as corroboration/fallback). Read grid filenames from the unique non-menu/non-checkbox opening button's aria-label, with visible filename text as a bounded fallback. Do not match whole-card text, preview contents, selection labels, or localized action-menu prefixes. Unknown/ambiguous items stay visible. Limit file candidates to observed file IDs/masonry file-kind markers so folder names are not accidentally filtered.
- [x] Hide the item wrapper in list; hide its directly owning `[data-masonry-item]` in grid. Mark only owned nodes; restore obsolete marks when an item is renamed/reused, roots change, the feature disables, route exits, or context invalidates. Do not detach native nodes or change app data.
- [x] While grid filtering hides at least one item, mark the verified masonry parent and temporarily use ordinary CSS grid auto-placement: scoped rules override child `grid-area` to auto and `transform` to none, and parent fixed height to auto. Preserve native responsive column definitions and gap; preserve DOM order, cards, actions, selection, and drag handlers. This deliberately uses rows while filtered; native masonry returns when disabled or no matching files remain. Do not overwrite native inline styles, measure/repack cards in JS, dispatch resize events to force updates, or reparent React nodes. Apply only to a verified common masonry parent; unknown layout stays visible with a recorded limitation rather than hiding a wrong ancestor.
- [x] Toolbar discovery: within the resolved main, prefer an observed filter icon fragment family (`filter-...`) inside a menu button, validate its small action group also contains the two view controls, and require uniqueness. Ignore sprite URL/hash and hashed classes. Fallback to the unique menu button in the structurally validated group with the two view toggles, excluding the extension's own pressed button. Reject ambiguity; do not select the first menu globally or English labels. Retain old-layout support only if a real fixture justifies it.
- [x] Insert a dedicated extension-owned control sibling before Filters; never move the native button. Reuse eye/eye-off SVG and localized label/tooltip keys. Render a compact icon with an accessible localized name, title, aria-pressed, focus indication, and native keyboard activation; visible text may be visually hidden to fit the toolbar. Use logical spacing, with immediate preceding sibling order proving placement. Write icon/label/attributes only when values differ to prevent self-mutation feedback.
- [x] Lifecycle: keep cheap route/shell discovery active so startup outside Library, button-driven navigation, browser history, delayed hydration, and root replacement all reconcile. Reuse a verified shared route signal if available; otherwise retain one cheap shell childList observer that checks route/root/control identity before scheduling bounded reconciliation. Do not patch history or introduce polling. On Library, use narrow toolbar/result observation; off Library disconnect those observers, restore marks/control/layout, and cancel pending work. Avoid duplicate overlapping broad subtree observers.
- [x] Disabled: control still mounts and persists setting changes; no result filtering observer or repeated item scans. Enabled: watch childList, characterData, and narrowly filtered filename/identity attributes needed for reused nodes. Ignore extension-owned mutations and no-op writes. Rebind observers after replacement. Use cancellable/token-guarded debounce and idempotent reconciliation. Context invalidation also removes new layout markers and cancels work.
- [x] Storage failures must not silently claim successful persistence: preserve/clarify existing error behavior and prove control state converges to sync storage when change notifications arrive. No setting migration or new key is needed.
