## Design and ownership

- [ ] Add `extension/shared/shortcut-bindings.js`: one pure owner for accepted codes, legacy-character conversion, empty-value conversion, equivalent-key comparison, event-key matching, and code/display mapping. Keep platform/localization presentation at its current boundary. Export one API for browser consumers and Node tests.
- [ ] Add `extension/shortcuts/search.js` and `extension/shortcuts/composer.js`. Each uses the existing browser/CommonJS wrapper convention and exports a small factory plus target definitions. Browser registrations live under one `CSPShortcuts` namespace; factories receive only explicit dependencies actually used.
- [ ] Keep modules passive at load time: no storage reads/writes, key listeners, observers, timers, or document mutation. `content.js` creates the pilot action instances once, supplies existing click/wait/composer-tool helpers, and connects the existing action map. Retained compatibility globals delegate to those instances.
- [ ] Move complete pilot behavior into its module, including its selectors and fallback ordering. Do not hide dependencies behind callbacks that merely invoke the old whole action body. Keep truly shared click/wait/tool primitives in their current owner and pass named references; do not move unrelated actions to make an extraction look complete.
- [ ] Preserve existing keyboard/modifier, IME, AltGraph and dispatch gates. The new binding module interprets keys; it does not register a competing dispatcher. `OPTIONS_DEFAULTS` still owns defaults, sync storage still owns settings, and ModelLabels still owns profile ordering/conflict policy.
- [ ] Expose `inspect(targetId, context)` and the concrete action methods from each factory. Inspection is synchronous/read-only where the DOM is already present. Return an element locally plus a serializable diagnostic record: target ID, surface/scope, prerequisites, named matching rule, candidate/eligible counts, selected element summary, status and reason.
- [ ] Use statuses `ready`, `missing`, `ambiguous`, `needs-state`, and `unavailable`. Scope candidates first, deduplicate the same element across rules, preserve documented rule priority, and refuse equally plausible eligible matches. Do not apply global uniqueness to repeated controls.
- [ ] Resolve again at activation. Use the same resolver for runtime and inspection. Menu actions explicitly prepare their state, wait within existing bounds, then resolve again; inspection reports closed/unrendered prerequisites without opening them. Dispose temporary waits/observers on success, timeout, or cancellation.
- [ ] Target definitions belong beside their production resolver. The existing development metadata references their IDs/owner/rule descriptors and retains scrape-state/probe policy. For migrated targets, derive overlapping selector/icon evidence from these definitions; do not maintain a second handwritten recognition list. Historical dump token matches remain labelled presence evidence, never executable-target proof.
- [ ] Extend `npm run shortcuts:catalog` to show each action's owner, target IDs, required state, and `shared-resolver` or `legacy` implementation. All existing actions remain catalogued; only the pilot gets new resolver diagnostics.
- [ ] Extend the existing live audit entry point with a new `--inspect-targets` flag and action filtering. It calls a read-only `CSPShortcuts.inspect(actionId)` facade in the installed content-script world and attaches results to the existing audit output. No separate dashboard, target database, click preparation, or broad capture occurs in this mode. Summary fields exclude conversation text, arbitrary HTML, and personal data.
- [ ] Preserve independent outcome assertions. Runtime and tests may share resolution code, but the expected popup/focus/tool state must come from independent fixture assertions. A returned success, selected element, or ready diagnostic is not a behavioral pass.
- [ ] Load the binding module before its consumers in popup and content paths, and feature modules before content startup. Explicitly update ZIP inclusion for added shipped paths while keeping development metadata excluded. Keep the separate document_start composer bootstrap intact.
